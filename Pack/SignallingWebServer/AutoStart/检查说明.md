# 信令服务器自启动检查说明

自启动用的是 Windows **计划任务** `PixelStreamingSignallingUser`，不是 Windows 服务，所以在 `services.msc` 里找不到它。安装时的账户登录后，任务会以该用户身份通过 `conhost.exe --headless` 在后台启动 `dist/SignallingWebServer.exe`，全程没有窗口；信令服务器和 UE 的优先级都是“高”。这个账户不登录，服务器就不会启动。

端口以 `dist/config.json` 里的 `StreamerPort`、`HttpPort` 为准（当前为 8888、6543）。下面的命令都在 `AutoStart` 目录下打开 PowerShell 执行。

## 1. 任务是否注册

图形界面：`Win+R` 输入 `taskschd.msc` → 任务计划程序库（Task Scheduler Library）→ `PixelStreamingSignallingUser`。

命令行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File user-task.ps1 status
```

| 结果 | 含义 | 处理 |
|---|---|---|
| 报错 / 找不到任务 | 未注册 | 用推流账户登录，双击 `install-user-autostart.bat` |
| `Running`（正在运行） | 正常 | 继续检查第 2–4 步 |
| `Ready`（准备就绪） | 已注册，但没在运行 | 双击 `start-user-autostart.bat` |
| `Disabled`（已禁用） | 已注册，但被禁用 | 重新双击 `install-user-autostart.bat` |

任务“操作”页里的程序应为 `conhost.exe`。如果是 `powershell.exe`，说明还是旧版任务，重新双击 `install-user-autostart.bat`。命令行查看：

```powershell
(Get-ScheduledTask -TaskName PixelStreamingSignallingUser).Actions.Execute
```

## 2. 上次运行结果

```powershell
Get-ScheduledTaskInfo -TaskName PixelStreamingSignallingUser
```

`LastTaskResult` 显示十进制，任务计划程序界面里的“上次运行结果”显示十六进制。任务经 conhost 启动，进程退出后结果码不反映退出原因，原因以第 4 步的日志为准。

| 十进制 | 十六进制 | 含义 |
|---|---|---|
| 267009 | 0x41301 | 正在运行 |
| 267011 | 0x41303 | 从未运行 |
| 3221225786 | 0xC000013A | 旧版任务的窗口被关闭或按了 Ctrl+C，重新双击 `install-user-autostart.bat` |
| 其他（含 0） | 其他 | 已退出，原因看第 4 步的日志 |

## 3. 进程和端口

```powershell
Get-Process SignallingWebServer | Select-Object Id, PriorityClass
Get-NetTCPConnection -LocalPort 8888,6543 -State Listen
```

两个端口都在监听，`OwningProcess` 等于 `SignallingWebServer` 的 `Id`，并且 `PriorityClass` 为 `High`，就是正常的。端口被其他程序占用时任务启动不了，要先关掉占用端口的程序。

浏览器连上后才会启动 UE，UE 进程的 `PriorityClass` 也应为 `High`（启动后 2 秒内生效）。把 `DasLianHuaDong` 换成 `dist/config.json` 里 `UEProgram` 的文件名（不含 `.exe`）：

```powershell
Get-Process DasLianHuaDong* | Select-Object Name, Id, PriorityClass
```

## 4. 日志

双击 `view-user-log.bat` 可以实时查看最新日志。日志文件是 `logs/SignallingUser-<时间>.out.log` 和同名的 `.err.log`，只保留最近 10 次。

正常启动时，`.out.log` 里会有这几行：

```text
WebSocket listening for Streamer connections on :8888
WebSocket listening for Players connections on :6543
SignallingWebServer started with UE program management enabled
```

没人连接过时 `.err.log` 应该是空的。每次 UE 被结束都会记一行 `streamer ... disconnected: 1006`，这是正常的；出现其他内容才需要处理。

## 5. 旧 Windows 服务已删除

早期方案把信令服务器注册成了 Windows 服务 `PixelStreamingSignallingServer`。只要这个服务还在，安装、开始、重启脚本都会报错退出。

```powershell
sc.exe query PixelStreamingSignallingServer
```

返回 `1060`（服务未安装）就是正常的。如果服务还在，用管理员 PowerShell 执行：

```powershell
sc.exe stop PixelStreamingSignallingServer
sc.exe delete PixelStreamingSignallingServer
```
